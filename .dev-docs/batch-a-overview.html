3iframe 与 Shadow DOM：自动合并

AI 不需要知道页面里有几层 frame。调用方式不变，输出里多出 frame 段落，ref 带前缀。

页面结构（示意：一个带支付 iframe 和 Web Component 的结账页）

主 frame（frameId 0） ref_3 heading "结账" ref_5 textbox "收货地址" ref_8 button "提交" ← 在 open shadow root 内
子 frame f3 · pay.example.com（跨域） f3.ref_1 textbox "卡号" f3.ref_2 textbox "有效期" f3.ref_4 button "支付"
孙 frame f7 · 3ds.example.com f7.ref_1 textbox "验证码"

虚线框是子 frame。没有任何元素的 frame（广告位、零尺寸 frame）不会出现在输出里。

read_page 输出（示意）

Page tree (9 elements, 3 frames, filter:interactive):

[ref_3] heading "结账"
[ref_5] textbox "收货地址"
[ref_8] button "提交"

── frame f3 · depth 1 · name="pay" · https://pay.example.com/card ──
[f3.ref_1] textbox "卡号"
[f3.ref_2] textbox "有效期"
[f3.ref_4] button "支付"

── frame f7 · depth 2 · https://3ds.example.com/otp ──
[f7.ref_1] textbox "验证码"

max_chars 预算按全部 frame 合计，超出时在整行边界截断，并提示可用 ref_id 聚焦某个 frame。

后续调用不变

form_input { tabId: 101, ref: "f3.ref_1", value: "4242 4242 4242 4242" }   → 自动投递到 frame f3
computer   { action: "left_click", tabId: 101, ref: "f3.ref_4" }       → 坐标沿 frame 链换算为主页面坐标
注入方式
内容脚本对 allFrames 注入，脚本幂等。去掉 csInjected 缓存后，重复注入的竞态一并消失。
已知限制
closed shadow root 无法穿透。跨域 iframe 的点击坐标已用三层跨源、带边框、缩放和滚动的页面验证，误差为 0，事件均为 trusted。
风险：子 frame 内的元素坐标相对自己的视口。计划用 CDP 的 DOM.getFrameOwner 和 DOM.getBoxModel 沿 frame 链累加偏移，编码前先用跨域测试页验证；行不通则退化为脚本派发事件（事件不是 trusted，会在结果里标注）。

4网络观测：失败原因 + 详情按需取

列表保持轻量，一行一个请求；需要细节时再按序号取，响应体不会默认塞进上下文。

network list（示意）

network { action: "list", tabId: 101, failedOnly: true }

Network (3 of 142, failedOnly):

#87  GET   FAIL [Fetch    ] https://api.example.com/orders     net::ERR_CONNECTION_RESET
#103 POST  FAIL [XHR      ] https://api.example.com/pay        blocked: cors
#119 GET   504  [XHR      ] https://api.example.com/status     HTTP 5xx

新增过滤：failedOnly、method、status（如 "4xx"、"5xx"）、urlPattern。缓冲区由 500 提到 1000 条。

agent 创建标签页时自报名字，扩展按名字找或建同名标签组，用户在浏览器上一眼看出哪个页面归谁。

tabs 的 action

action参数说明
listgroup?列出标签页，显示所属组、窗口、是否激活，可按组过滤
createurl? active?=true group?带 URL 时等页面加载完成再返回

6同标签页串行化

写操作按 tabId 先进先出排队，读操作不排队。每次调用保持原子性。

写：tab 101 · agent-a
click 提交
写：tab 101 · agent-b
排队中 type 验证码
读：read_page
立即执行
handle_dialog
绕过队列
写操作执行中 排队等待 读操作，不排队 绕过队列
进队列
  • computer 的点击、输入、按键、滚动、拖拽
  • form_input、navigate、file_upload
  • javascript_tool、tabs 的 reload
不进队列
  • read_page、find、get_page_text、截图
  • 日志、network、wait_for
  • handle_dialog：dialog:"manual" 的弹窗会卡住持锁的点击，它必须绕过队列，否则死锁
排队超过 30 秒返回"标签页忙"。工具整体超时会释放锁，一个卡死的调用不会拖垮整个标签页。它保证单次调用的原子性，不保证两个 agent 的操作逻辑不冲突，所以仍建议每个 agent 用自己的标签页。

8默认选择与风险

我替你做的默认选择（可推翻）
  • tabs.create 的 active 默认 true
  • 响应体截断上限 20 KB，超出用 saveTo 落盘
  • 写操作排队超时 30 秒
  • 不支持 closed shadow root
  • 本批不含 tabs 之外的窗口管理
风险
  • 跨域 iframe 内元素的点击坐标，编码前先做实验
  • 响应体只在浏览器会话内保留，可能过期
  • 破坏性改动，需要同步各客户端的提示词
  • 串行化不能防止两个 agent 逻辑冲突
