3storage：读写登录态

很多站点把 token 放在 localStorage 而不是 Cookie。它和 cookies 配套，才能完整覆盖登录态。

action参数说明
listtabId area列出键和值的摘要，长值截断。area 为 local 或 session
gettabId area key取单个键的完整值，超过上限截断
settabId area key value写入
removetabId area key删除单个键
cleartabId area清空该区域
idbtabIdIndexedDB 只读摘要：库、版本、对象仓库、记录数。不读记录内容，不写入

输出（示意）

storage { action: "list", tabId: 101, area: "local" }

localStorage of https://shop.example.com (4 keys):

token        "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1aWQiOjQy…"   (812 B, truncated)
theme        "dark"
cart:count   "3"
lang         "zh-CN"

storage { action: "idb", tabId: 101 }

IndexedDB of https://shop.example.com (2 databases):

cart-db  v3
  items   ~ 12 records, keyPath: id
  meta    ~ 1 record
sync-db  v1
  queue   ~ 0 records, autoIncrement

记录数通过对象仓库的 count() 取得，打开数据库用当前版本，不会触发升级。

作用范围
只作用于该标签页主 frame 所在的源。iframe 的源不同，本批不支持，传了会得到明确提示。
敏感程度
能直接读写 token，和 cookies 工具同级敏感。README 的安全说明里会补一条。

4请求拦截与 Mock

模拟接口失败、慢响应和假数据，用来测前端的容错逻辑，也能屏蔽统计脚本。

一条规则怎么生效（示意）

1 页面发请求浏览器暂停该请求
→
2 匹配规则URL 通配符 + 可选的 method
→
3 执行行为按规则处理
fail让请求失败，可选原因：断网、拒绝连接、超时等
fulfill返回自定义状态码、响应头、响应体，请求不会到真实服务器
delay等待若干毫秒后原样放行
未匹配立即放行，不影响页面

三个工具（示意）

intercept_add { tabId: 101, urlPattern: "*api.example.com/orders*", action: "fulfill",
                 status: 500, headers: { "content-type": "application/json" },
                 body: "{\"error\":\"mock\"}" }
Rule r1 added (fulfill 500) on tab 101

intercept_add { tabId: 101, urlPattern: "*analytics*", action: "fail", errorReason: "BlockedByClient" }
Rule r2 added (fail BlockedByClient) on tab 101

intercept_add { tabId: 101, urlPattern: "*/api/search*", method: "POST", action: "delay", delayMs: 3000 }
Rule r3 added (delay 3000ms) on tab 101

intercept_list { tabId: 101 }
Rules on tab 101 (3):
r1  fulfill 500   *api.example.com/orders*      hits 4
r2  fail          *analytics*                   hits 17
r3  delay 3000ms  POST */api/search*            hits 0

intercept_remove { tabId: 101, ruleId: "r1" }     → 删除 r1
intercept_remove { tabId: 101 }                   → 清空全部规则，并关闭拦截

规则按添加顺序匹配，第一条命中的生效。规则只属于它所在的标签页，标签页关闭时一并清除。

风险一：规则丢失导致请求卡死
MV3 的 Service Worker 可能被浏览器回收。如果规则只在内存里，浏览器那边的拦截仍然开着，被暂停的请求没人放行，页面会一直卡住。
做法：规则存进 chrome.storage.session，Service Worker 恢复后重新加载；恢复不了就主动关闭拦截。
风险二：页面跳转会断开调试器
现有代码在页面开始加载时会断开调试器，只有 trace 和 emulate 的标签页例外。拦截规则也要加进这个例外，否则跳转一次规则就失效。
原文：fulfill 响应体只支持文本，二进制留到后续批次 —— C 批 v2.2 已补齐（bodyBase64），跨域带凭据的 Mock 也已自动补 access-control-allow-credentials。

5emulate 扩展：设备、位置、时区、语言

所有新参数并入现有 emulate，沿用 reset:true 一键还原，旧调用不受影响。

内置设备预设（示意）

iphone-15393×852
@3x
pixel-8412×915
@2.625x
ipad-air820×1180
@2x

每个预设包含视口、像素比、触摸模拟、移动端标记和对应的移动端 User-Agent。也可以不用预设，直接传 width、height、deviceScaleFactor、mobile 自定义。

参数一览

参数说明
deviceiphone-15 / ipad-air / pixel-8，一次设置视口、像素比、触摸、移动端 UA
width height deviceScaleFactor mobile自定义视口。同时传 device 时，显式参数覆盖预设里对应的值
latitude longitude accuracy?地理位置。经纬度必须成对传入
timezoneIANA 时区名，例如 Asia/Tokyo
locale语言区域，例如 ja-JP，影响 navigator.language 和日期数字格式
reset清除本工具设置过的全部覆盖，包括新增的这几项

输出（示意）

emulate { tabId: 101, device: "iphone-15", timezone: "Asia/Tokyo", locale: "ja-JP",
           latitude: 35.68, longitude: 139.76 }

Emulation applied: device iphone-15 (393x852 @3x, mobile, touch), timezone Asia/Tokyo, locale ja-JP,
geolocation 35.68,139.76. Overrides last until the debugger detaches or reset:true.
Note: the page can only read the location if this site already has location permission in Chrome.
地理位置的限制：我们只能改“位置值”，不能代替用户授权。站点没有位置权限时页面会弹授权框，这个框点不了。需要先在 Chrome 里给该站点授权一次，这句话会写进工具描述。

6默认选择与风险

我替你做的默认选择（可推翻）
  • 预设只放 iphone-15、ipad-air、pixel-8 三个
  • 设备 UA 里的浏览器版本取当前稳定版
  • storage 不对值打码，和读写登录态的目的一致；list 里长值截断到 200 字符
  • storage 只支持 local / session 的写入，IndexedDB 只读
  • 拦截规则按标签页隔离，标签页关闭即清除
  • fulfill 只支持文本响应体
  • 不做权限授予
风险与待验证
  • Browser 域被拒只是文档结论，编码第一步先实验
  • Fetch 域在真实扩展里的行为，尤其和 Network 域同时开启时，需要实测
  • Service Worker 被回收后的规则恢复与兜底，要专门测
  • storage 能直接改 token，需要在 README 安全说明里写明
  • 工具总数增加到 23 个，上下文占用变大
